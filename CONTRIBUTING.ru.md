# Участие в разработке yumeclient

[English](CONTRIBUTING.md) | **Русский**

Сообщения об ошибках, записи отпечатков и pull request'ы приветствуются. Пишите на русском или
английском. Об уязвимостях сообщайте закрыто, см. [SECURITY.ru.md](SECURITY.ru.md).

## Сообщение об ошибке

Откройте issue с формой «Bug report» и укажите:

- `yumeclient.__version__`, версию Python и ОС;
- профиль (`client_identifier`) и параметры сессии;
- минимальный код, на котором видна проблема, и что вы ожидали вместо этого;
- для исключения: его тип и атрибуты `kind`, `stage` и `retryable`
  ([таймауты и ошибки](docs/ru/timeouts-and-errors.md));
- для неправильного запроса или ответа: вывод `r.trace()`. Он скрывает значения query, cookie,
  учётные данные и заголовки, похожие на токены, а от тел оставляет только длину и SHA-256
  ([диагностика](docs/ru/diagnostics.md#responsetrace)). Прочитайте его, прежде чем публиковать.

## Отпечаток не совпадает с браузером

Если профиль не похож на браузер или приложение, в честь которого назван, откройте issue с
формой «Fingerprint mismatch». Напишите, что отличается и откуда это известно:

- одна и та же страница, полученная настоящим клиентом и yumeclient: например, JSON
  `https://tls.peet.ws/api/all`, открытый в браузере, и `r.fingerprint` из yumeclient;
- версию браузера, его ОС и сеть (прокси, VPN): от них зависят некоторые поля.

Safari на macOS, iOS и iPadOS и профили мобильных приложений ещё не сняты с настоящих
устройств ([ограничения](docs/ru/limitations.md)). Записи с этих устройств полезнее всего.
Как записать рукопожатие HTTP/3 с помощью `scripts/h3_capture.py`, описано в разделе
[Разработка](docs/ru/development.md#http3-и-quic).

## Pull request'ы

Сборка и тесты (Go 1.24.1+ и компилятор C; на Windows — MinGW-w64, `gcc` в `PATH`):

```bash
./scripts/build-native.ps1          # Windows; Linux/macOS: sh ./scripts/build-native.sh
pip install -e ".[test]"
python -m pytest -q                 # без сети: тесты поднимают свои локальные серверы
(cd native && go test ./...)
python scripts/third_party.py check
```

- **Исправление приходит с тестом, который без него падает.** Тесты работают с локальными
  серверами (HTTP/1.1, HTTP/2 на сырых кадрах, HTTP/3 на aioquic, HTTP CONNECT- и
  SOCKS5-прокси), интернет не нужен. Чтобы проверить тест на прошлом релизе, укажите в
  `YUMECLIENT_LIBRARY` нативную библиотеку этого релиза.
- **Upstream-модули** (`native/third_party/`) — копии с патчами. Отредактируйте копию,
  выполните `python scripts/third_party.py diff` и закоммитьте и копию, и патч в
  `native/third_party/patches/`. Каждую правку помечайте комментарием `// yumeclient: <причина>`.
  CI проверяет, что каждая копия равна upstream плюс её патч.
- **Только нужные изменения.** Не переформатируйте код, который не меняете: часть Go-файлов не
  прогнана через gofmt, и переформатирование целого файла спрячет настоящую правку.
- **Документация на двух языках.** Английские страницы лежат по обычным путям (`docs/*.md`,
  `USAGE.md`, ...), русские — рядом (`docs/ru/*.md`, `USAGE.ru.md`, ...). Меняйте обе;
  `tests/test_docs_i18n.py` проверяет, что у двух версий одинаковая структура. Если вы пишете
  только на одном из языков, укажите это в pull request'е.
- **Документация следует коду.** Значения по умолчанию, типы исключений, тексты ошибок и
  поведение на проводе в документации сверены с кодом или тестом. Скрипты из `examples/`
  запускаются в тестах, а Python-фрагменты документации должны компилироваться.
- **Changelog.** Опишите видимые пользователю изменения в разделе `[Unreleased]` в
  `CHANGELOG.md` и `CHANGELOG.ru.md`.

Структура проекта, запись отпечатков браузеров и выпуск релиза описаны в разделе
[Разработка](docs/ru/development.md).

Отправляя изменения, вы соглашаетесь, что они распространяются по [лицензии MIT](LICENSE).
